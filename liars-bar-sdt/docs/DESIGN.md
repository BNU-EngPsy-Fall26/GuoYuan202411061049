# 《骗子酒馆 · 识谎局》
## 交互式信号检测实验网站 —— 设计提案 v1（待审）

> **课程作业一**：构建一个信号检测论交互式实验网站
> **原型参考**：`Liar's Bar`（中文译名"骗子酒馆"/"骗子酒吧"），Curve Animation 开发并发行，2024-10-02 于 Steam 抢先体验上线，获 2024 年 Steam 大奖"最具创意游戏玩法"。核心玩法为谎报牌面/骰子点数互相欺骗，被识破者接受俄罗斯轮盘赌惩罚。
> **技术路线**：纯前端 HTML + CSS + JavaScript（Canvas 2D 渲染），**零第三方依赖、零构建步骤**，双击 `index.html` 即可运行。

## 0. 一句话设计

把"识破对手吹牛"这件事，做成一个标准的 **Yes/No 信号检测任务**。

每一轮，对手把牌推到你面前，报出一个点数。你要判断的只有一件事——**他在说谎，还是在说实话**。
**说谎 = 信号（Signal）**，**说实话 = 噪音（Noise）**，你按下按钮的那一刻，就是一次信号检测。

## 2. 原理：信号检测论映射（核心）

### 2.1 状态空间

| | 客观事实 | 代号 | 游戏里的含义 |
|---|---|---|---|
| 噪音 | 对手说真话 | **N** | 他手上真有这几张牌 |
| 信号 | 对手在说谎 | **S** | 他手上没有，纯属吹牛 |

### 2.2 证据变量与决策规则

玩家不可能直接知道对手手上的牌。他只能依据一个**内部证据变量 x**（主观"可疑度"）做判断：

```
x | N  ~  Normal(μ = 0, σ = 1)      ← 说真话时，你看到的证据
x | S  ~  Normal(μ = d′, σ = 1)     ← 说谎时，你看到的证据
```

玩家设定一条**门槛 c**：`x > c → 揭穿（报"有信号"）`；否则 `相信（报"无信号"）`。

- **d′** 是两条分布中心的标准化间距 → 衡量"破绽有多明显"（客观难度）。
- **c** 是门槛相对两分布中点的偏移 → 衡量"你有多容易起疑"（主观倾向）。

### 2.3 四种结果：从统计术语到酒馆后果

| | 你报"揭穿"（Yes） | 你报"相信"（No） |
|---|---|---|
| **对手说谎（S）** | **H 命中** — 当场抓包，对手喝罚酒，你得分 | **M 漏报** — 你被骗过去，你喝罚酒 |
| **对手说实话（N）** | **FA 虚报** — 你冤枉了好人，你喝罚酒 | **CR 正确拒绝** — 稳稳跟牌，无事发生 |

这张表会**直接印在游戏内的"规则卡"上**，用酒馆语言表达统计概念，玩家玩三局就会背下来。

### 2.4 结算公式（游戏结束后自动计算）

设 H、M、FA、CR 分别为四类反应的次数：

```
命中率    p(H)  = H / (H + M)                 保留率 / 击中率
虚报率    p(FA) = FA / (FA + CR)              误报率
辨别力    d′    = z(p(H)) − z(p(FA))          z 为正态分布逆函数（probit）
判断偏向  c     = −0.5 · [ z(p(H)) + z(p(FA)) ]       c > 0 保守，c < 0 激进
似然比    β     = exp(c · d′)                 β > 1 保守，β < 1 激进
准确率    ACC   = (H + CR) / N_total
```

**极值修正**：当某格为 0（例如一局内一次都没虚报）时 `z(0) = −∞`。按 Hautus (1995) 的蒙特卡洛比较结果，采用 **log-linear 规则**（每格频次 +0.5，总数各 +1）优于 `1/(2N)` 规则：

```
p(H)  = (H + 0.5) / (H + M + 1)
p(FA) = (FA + 0.5) / (FA + CR + 1)
```

界面上会在修正生效时打一个 **"已修正"** 角标，并说明原因——不悄悄改数据。

### 2.5 加分项：先验概率 P(S) 与最优门槛

作业要求"设定先验概率 P(S)"。它不只是个生成参数，它直接决定**理性玩家的最优门槛**。

给定"对 +1 / 错 −1"的对称收益矩阵，贝叶斯最优似然比为：

```
β_opt = [ P(N) / P(S) ] · [ (V_CR − V_FA) / (V_H − V_M) ] = P(N) / P(S)
c_opt = ln(β_opt) / d′ = ln( P(N) / P(S) ) / d′
```

于是游戏能做一件真实实验做不到的事：**在结算界面告诉你"你该怎么判"，再和你实际的门槛对比**。
例如谎话率 80% 时，`c_opt ≈ −1.39 / d′`，说明理性策略应当明显偏向"爱怀疑"。这个模块放在"进阶教学"页，默认折叠。

## 3. 玩家到底在看什么：证据通道的生成模型

这是整个设计里最容易含糊、也最需要说清的一点，**必须在 README 里明写**。

### 3.1 试次生成算法（伪代码）

```js
// 开局时先定好客观状态序列：区组随机配额 + Fisher–Yates 洗牌
function buildStateSequence(trials, pSignal) {
  const k = clamp(Math.round(trials * pSignal), 1, trials - 1);
  const arr = [...Array(trials).keys()].map(i => i < k);
  shuffle(arr);                       // 保证 P(S) 恰好等于设定值，且两类都非空
  return arr;
}

function generateTrial(params, isLie) {
  const x    = normalRandom(isLie ? params.dPrime : 0, 1);   // 内部证据（玩家不可见）
  const tell = clamp(x + normalRandom(0, σ_disp), -3, 3);    // 证据 → 可感知强度
  const claim = renderClaim(isLie);                          // 喊牌内容（纯装饰）
  return { isLie, x, tell, claim };
}
```

> **实现时的一处修正**：初稿是按 P(S) 每个试次独立掷骰子，但自检发现
> P(S)=0.1、20 试次的设置下有 `0.9^20 ≈ 12%` 的概率一个信号试次都抽不到，
> 命中率直接算不出来。最终改为**区组随机配额法**——先验概率恰好等于设定值，
> 且两类试次必然非空，这也是心理物理学里更标准的做法。

### 3.2 破绽的可视化

对手所在区域渲染一层**动态噪点**（酒馆灯光下的颗粒感）。噪点之上叠加一个"破绽"信号：可以是眉梢的一下抽动、指节敲桌的节奏、嘴角的一丝不自然。**它的对比度 / 清晰度 / 出现频率由 `tell` 线性控制**：

```
contrast = 0.10 + 0.16 · tell      // tell 越大，"破绽"越明显
jitter   = 0.5 + 0.9 · max(0, tell) // 越可疑，动作越不稳
```

> **2026-10-06 实现后修订（已生效，README 4.1 为准）**
>
> 上面这两行是 v1 提案的写法，实装时改掉了，原因是它有两个问题：
>
> 1. **直接在 tell 上乘增益会截断负半轴。** 负的 tell 会把对比度压到 0 以下被 clamp，
>    一半的噪音试次挤在同一个下限上，那段信息被抹掉，设定的 d′ 在画面上失真。
>    现在先归一化成 `k = (tell + 3) / 6`，整条 ±3σ 区间严格单调。
> 2. **单通道太弱，读不出来。** 实装初版只有"柔光不透明度"一个通道，
>    `tell = 0` 与 `tell = 1` 之间只差 0.26 的不透明度，而且破绽被画在颗粒噪点层
>    **下面**，被糊掉一层对比度，实际几乎看不出区别。现在改成
>    "不透明度 / 柔光半径 / 核心亮点 / 头肩抖动"**四通道联动**，绘制顺序调到噪点之上。
>
> 多开通道**不会**改变理论 d′：d′ 对严格单调重映射是不变的（H 与 FA 在对应判据下的
> 取值不变）。四个通道摊的是同一份信息，只是让它更好读。像素实测：
> 破绽区域平均亮度 `tell = −2 → 35.9`、`0 → 46.2`、`+2 → 68.4`，严格单调。
>
> 另外，破绽落点从 v1 的"眉梢 / 嘴角 / 眼神 / 额角"改成"眉梢 / 眼角 / 嘴角 / 颧骨"——
> 原来的"额角"实际上压在礼帽上，光斑看着像浮在帽子上，不像表情破绽。

诚实地说：这本质上就是教科书里最经典的 **"噪声背景中的目标检测"** 任务，只是套了一层酒馆的皮。这样做的好处是——

> **d′ 是被"设计"出来的参数，不是事后拟合出来的。** 助教打开 README 就能看穿整条生成链，这在方法学上是干净的，而不是把 d′ 当成一个"游戏难度等级"随便标个数字。

### 3.3 额外红利：可以立刻验证统计量算得对不对

因为信号是我们自己生成的，我们**精确知道真值 d′_true 和 P(S)_true**。于是结算界面可以多给一栏：

> 真值 d′ = 1.00 ／ 你的估计 d′ = 0.94 ／ 偏差 −0.06

真实心理学实验永远做不到这件事。这既证明了代码正确，本身也是极好的教学可视化（"为什么 40 试次估出来的 d′ 会抖"）。

## 4. 游戏流程

### 4.1 全局流程

```
① 进入酒馆（设置参数）
        ↓
② 教程：2 个示范试次，逐步讲解什么叫命中/虚报
        ↓
③ 单试次循环 × N（每局 20–60 试次，默认 40）
        ↓
④ 局结算：混淆矩阵 + p(H) / p(FA) / d′ / c / 准确率 + 可视化
        ↓
⑤ 多局历史：参数对比、历任成绩、排行
        ↓
      ↻ 返回 ① 换参数再战
```

### 4.2 单试次状态机（游戏的核心循环）

| 阶段 | 画面 | 时长 |
|---|---|---|
| **1 发牌 & 喊牌** | 对手把牌"啪"地扣在桌上，气泡报数："两张 K。" | 0.8 s |
| **2 观察窗** | 灯光聚焦对手面部，破绽开始显影；**绕对手头部的环形倒计时** | **3 s 限时**（可设 3/5 s，或关闭） |
| **3 你的判断** | 两个大按钮：**"相信他"** / **"你骗人！"**（快捷键 `J` / `K`） | 直到按键或超时 |
| **4 揭示与计分** | 牌翻开 → 红线划出判定结果 → 罚酒动画 / 加分动画 | 1.2 s |
| **5 间隙** | 简短旁白 + 当前累计成绩缩略条 | 0.6 s |

**超时处理**：观察窗结束时若仍未按键，自动记为"相信"，并在结果区用灰色标注"超时"。这一点同时满足作业"刺激限时"的要求，也避免玩家无限拖延。

> **2026-10-06 实现后修订：单屏布局是硬约束**
>
> v1 稿把喊牌气泡做成 HTML 浮层钉在画面右上角，游戏屏也是普通流式布局 —— 实装后发现两个
> 直接损害数据的问题：气泡离破绽（脸部）隔了半屏，玩家要抬头去找；Canvas 宽度铺满、
> 高度自适应，在常见笔记本上必然把判断按钮挤到折叠线以下，玩家得滚动才按得到。
>
> 现在：喊牌内容与 `J` / `K` 提示都画进 Canvas 内部（贴着对手与画面底部），
> 游戏屏改成视口自适应的弹性布局并锁掉页面滚动，**酒客 / 喊牌 / 提示 / 判断按钮 /
> 置信度按钮永远同屏**。理由不是好看——反应时从观察窗开始计时，滚动与视线往返的时间
> 都会被算进 RT，数据就废了。置信度那一行在非作答阶段**保留占位但不可见**，
> 避免它出现／消失时把画面顶一下（那等于在提示玩家"该答了"）。

### 4.3 局内设置

- 每局试次数：**20 / 40 / 60**（默认 40，硬性满足"每局 ≥ 20 试次"）
- 试次顺序：S/N 随参数独立抽样，**每局内参数固定**（这是估出单一 d′、c 的前提）

## 6. 结果计算与展示（占 30 分，也是加分主战场）

### 6.1 必做项

1. **混淆矩阵**：H / M / FA / CR 四个计数，四色分区，鼠标悬停显示该格子对应的游戏场景原话。
2. **指标卡**：`p(H)`、`p(FA)`、`d′`、`c`（附 β）、**准确率**。
3. **理论值与估计值对照**：真值 d′ vs 估计 d′（见 3.3）。
4. **一句人话总结**：自动生成，例如——"你抓到了 8 次里的一半骗子，但也冤枉了 3 个老实人。你的门槛偏保守（c = +0.32），下次可以更爱怀疑一点。"

### 6.2 加分项（作业明列的三条，全部覆盖）

| 作业加分项 | 我们的实现 |
|---|---|
| 分布随 d′ 变化、c 滑块、ROC 曲线 | **交互式理论面板**：拖动 d′ 与 c 滑条，实时看两条正态分布、门槛线、阴影区域、ROC 工作点联动 |
| 多局数据对比 / 排行榜 | **历史页**：每局一行（参数 / d′ / c / 准确率 / 时间戳），可勾选 2–3 局叠加对比；本地存储的最佳成绩榜 |
| 界面美观、有场景代入感 | 全套酒馆美术 + 叙事旁白（见第 7 节） |
| *（自加）* 经验心理测量函数 | 每试次的内部证据 x 会被记录但不显示；结算后按 x 分箱画 `P(揭穿 | x)` 曲线，**反推你自己的主观门槛在哪** |

## 7. 画面风格与交互叙事

### 7.1 基调

**Noir 酒馆**：昏黄吊灯、木质圆桌、烟雾、暗角。镜头是第一人称俯视桌面 + 对面坐着酒客。不是恐怖游戏，是**有质感的、slow-burn 的对峙感**。

### 7.2 色板

| 用途 | 色值 | 说明 |
|---|---|---|
| 深色底 | `#0E0B08` / `#16110C` | 夜幕与墙面，占画面 60% |
| 暖黄灯光 | `#E0A83C` / 高光 `#F5D08A` | 吊灯、边缘光、重点 UI |
| 血红强调 | `#8E2B2B` / `#C0392B` | 罚酒、揭穿瞬间、错误反馈 |
| 台呢墨绿 | `#1B3A32` | 桌面质感 |
| 纸牌米白 | `#EFE6D4` / 墨字 `#241C13` | 卡牌与文本面板 |
| 烟雾灰 | `#6B6255` | 次级文字、未激活控件 |

**功能区配色独立**：数据可视化用蓝 `#378ADD`（噪音分布）与琥珀 `#BA7517`（信号分布），保证在暗色场景里依然清晰可读——**氛围归氛围，数据归数据，两套颜色不打架**。

### 7.3 字体

- 标题：**思源宋体 / Noto Serif SC**（衬线，有年代感）
- 正文与 UI：系统无衬线（`system-ui`, `"Microsoft YaHei"`）
- 数字：等宽（`ui-monospace`），让 d′、c 一列对齐

字体全部走系统回退，不引入外部字体文件，保证离线可跑。

### 7.4 动效与音效

- 发牌：位移 + 轻微旋转，带缓动
- 倒计时：环形进度条随剩余时间变色（黄 → 红）
- **揭穿成功**：镜头震动 + 红闪 + 对手卡牌翻面
- **被冤枉 / 被骗**：画面降饱和 + 暗角收拢 0.3 s
- 音效（可关）：卡牌"啪"、心跳（观察窗）、酒杯碰击、钟声——全部用 **Web Audio API 现场合成**，不带音频文件

### 7.5 叙事文案

旁白用第一人称酒馆口吻，四种结果各写一句，让统计结果具有情绪重量：

- **H**：「你的手指压住了他的袖口。他手背上那道抽动，刚才还在。」
- **FA**：「你喊了'你骗人'。牌翻开，是真的。他笑了，把酒推到你面前。」
- **M**：「你放下了手。他慢慢把牌收回去，没看你。」
- **CR**：「你什么都没说。他把牌推给下家，一切正常。」

**动漫风格**的实现方式（全部程序化 Canvas 2D，无贴图）：

- 脸型用**贝塞尔曲线**勾尖下巴轮廓，而不是椭圆；下颌描一圈暗边
- 头发分**后层**（长发/发髻/丸子）+ **前层**（发顶 + 5 缕交错刘海 + 内收鬓角 + 发丝走向线 + 天使轮高光）
- 眼睛：巩膜（压暗的暖白，不用纯白）+ 虹膜径向渐变（暗环 → 亮芯）+ 瞳孔 + 高光点 + 睫毛 + 眉毛
- 配饰：帽子（平顶帽 / 圆顶礼帽，描暗边）、眼镜、耳环、项链、领结 / 胸针、披肩、纽扣

**④ 形象选择的公平性约束（关键）**

形象**一局抽一次、整局不变**，用 `Math.random` 抽取——**故意不走可播种 RNG 流**，
否则同一个种子会连带固定形象，等于给"重放"开了后门。形象本身**不携带任何真假线索**，
只影响画面外观。

但"换形象"有一个隐蔽的风险必须堵：**破绽是脸上的亮斑，如果某个形象的落点底色本来就更亮，
那张脸的破绽就更好读**——等于按形象偷换难度。所以：

- 破绽四个落点（`眉梢 / 眼角 / 嘴角 / 颧骨`）的坐标做了微调，**避开眼白与镜片中心**
  （眼白是画面里最亮的区域，垫高了底色就等于改了难度）
- 巩膜统一压暗为 `#CFC4AE`（不是纯白）
- 老年形象的发色逐级压暗（`#6B6157` → `#5E564C` → `#4E463C`），垂发与鬓角内缘收进 `0.80rx` 之外，
  刘海下段渐变再压 `0.78`

**量化验证**：写了一个像素探针，逐个人物 × 逐落点渲染 `tell = −2 … +2`，采样破绽区域平均亮度：

```
底色（tell = −2）  min 67.8  max 88.7  极差 20.9
跨度              min 74.4  max 84.7
最小档差          min 16.2  max 18.8
非单调组数        0 / 24          （6 人物 × 4 落点）
```

修订前老年女的底色是 110/97/95，其余人物 50–70，极差 60——确实存在难度泄漏，已修复到 20.9。
**结论：破绽在六张脸上都严格可读，且不同形象之间的难度差已被压到可忽略。**

### 7.7 （2026-10-08 晚）第二版：躯干、画序、卡牌

7.6 那轮把**脸**做细了，但**身体和卡牌仍是"形状的堆砌"**。这一轮处理三件事。

**① 躯干：十层结构**

| 层 | 内容 | 为什么必须有 |
|---|---|---|
| ① 底形 | 颈根 → 斜方肌 → 肩峰转角 → 三角肌 → 上臂外缘 | 见下方"肩" |
| ② 体积 | 顶光竖向明暗 + 两肋压暗 + 人字呢织纹（16×16 程序化贴片平铺） | 一块平色无论轮廓多准都像纸片 |
| ③ 轮廓线 | 整圈描暗边 | 不描边会和暗背景糊在一起（脸也是这么处理的） |
| ④ 肩部轮廓光 | 吊灯从头顶扫下来的暖边 | —— |
| ⑤ 臂缝（袖窿） | 宽阴影带 + 缝线 + 受光边 三笔 | 单画一条细线在深色大衣上等于没画 |
| ⑥ 衣领座 | 绕脖子根的一道立领 | 压住脖子与躯干的接缝 |
| ⑦ 内搭 | 敞开的 V 字里的衬衫 / 马甲 | 见"V 边共用" |
| ⑧ 驳头 | 带缺口的平驳头，左右各一片 | 缺口是西装最好认的特征 |
| ⑨ 细节 | 扣子、口袋巾、胸针、领带 | —— |
| ⑩ 褶皱 | 前襟到袖子的一道长褶（暗线 + 亮边成对出现） | 单画暗线在深色大衣上等于没画 |

**肩不能画成一段圆滑的弧**——那样整个人像一座山。拆成三段：斜方肌（平缓）→ 肩峰转角（陡）→ 三角肌外圆（再往外撑开）。转角那一段是关键。

**V 边共用一组控制点**：`vGeom()` 返回 V 的端点与两条贝塞尔控制点，`underLayerPath`（内搭）和 `lapelPath`（驳头）都调 `vEdgePath` 走同一条边。这样两片衣服的边严丝合缝，不会出现"驳头压不住衬衫、露出一条缝"。

**配色整体提亮**：旧版 `#2C2219` 这种近黑大衣在暗场里看不出任何层次。六件衣服的基色上调一档（青年男 `#2C2219 → #3E3124`，青年女 `#2E2028 → #402F3C`），`collar` 同步提亮。

**衣着按形象区分**（`wear` 字段）：

| wear | 用于 | 表现 |
|---|---|---|
| `vest` | 青年男 | 马甲 + 深色领带 |
| `suit` | 中年男 | 平驳头西装 + 领带 + 口袋巾 |
| `cardigan` | 老年男 | 青果领开衫 + 一排扣 |
| `blouse` | 青年女 | 罩衫 + 领口贴边 + 胸针（内搭压暗一档） |
| `dress` | 中年女 | 连衣裙，无驳头 |
| `shawl` | 老年女 | 披肩（带罗纹）罩在整件衣服外面 |

**② 画序：人物挪到桌子后面**

`drawTable` 从人物之前挪到之后，并新增常量 `TORSO_BOTTOM = 412`（比桌面远沿 y≈390 再低一截）。台呢于是盖住上身下沿，人物成为"坐在桌子后面"，而不是一尊悬在桌沿上的半身像。

安全检查：桌上的酒瓶在 x=175、酒杯在 x=705，人物半宽 ±200，两者不重叠，不会出现"杯子被人挡住"。

**③ 卡牌：按真扑克重画**

- 牌面：纸面渐变 + 双线内框 + 左上/右下两组角标（右下倒置）+ 中央大花色；♠♥♦♣ 全部矢量绘制（新增 `drawDiamond` / `drawClub` / `drawPip`）。
- 牌背：红底渐变 + 米色双线框 + 斜向菱格 + 中央椭圆徽章（内嵌黑桃）+ 四角小菱形。
- 厚度：牌身下压一层 2.2 px 暗色 —— 牌是有厚度的纸。
- 尺寸 `70 × 98`，底边 495，与按键提示行（501 起）留 6 px，不打架。
- **花色由牌面唯一决定**（`RANK_SUIT` 写死），因此不携带任何信息；写死而非每局随机，是为了同局重放时画面完全一致。
- 揭示标记（红叉 / 绿勾）改为"暗色外缘 → 上色 → 高光"三笔，尺寸收到贴着牌组，整体旋转 −0.05 rad。

**④ 删掉卡面下方那行小字**

旧版在牌心下方 28 px 写"不是他要的牌 / 正是他报的牌"。删除，理由是**完全冗余**——同一条信息已经由三处表达：画面顶部的大字判定、画布下方的结果条（H/M/FA/CR + RT）、以及压在图上的红叉/绿勾。而且它挤在 70 px 宽的牌里，既看不清又挡掉半个牌面。**信息没丢，只是不再重复第五遍。**

同时给顶部大字判定加了圆角底衬：它刚好压在对手的帽子/头发上，无底衬时字与头发糊在一起，而这行字是玩家唯一能立刻读到"本局算对还是算错"的地方。

**验证**：六形象整场景对照图 + 3 倍躯干特写逐张人工核对；卡牌区逐点像素检查（旧小字位置暗像素 0、中央大花色 1017、角标 141、红叉 467、绿勾 509、牌背徽章 205）；破绽单调性回归 0/24 非单调；完整一局 20 试次 + 20 置信度、一屏无滚动、0 报错。

### 7.8 （2026-10-08）第三版：颈肩过渡层

**症状**：头是悬空的 —— 下巴与身子之间什么都没有，墙纸直接透过来。

**根因（纯几何）**

| | 位置 |
|---|---|
| 脸的下巴收完于 | `y = 1.03 ry`（该处脸宽仅 `±0.17 rx`） |
| 脖子（旧） | `±0.40 → ±0.52 rx` |
| 躯干肩线起点（颈根） | `(±0.94 rx, 1.68 ry)` |

于是 `|x| ∈ [0.52, 0.94] rx`、`y ∈ [1.03, 1.65] ry` 这两片三角区内**没有任何图元覆盖**——正面半身像最典型的"断头"缺口。注意它和"脖子画没画"无关：脖子一直都在，只是**不够宽、也不该宽到肩**，颈侧那一块必须另有东西接。

**修法：新增 `neckBasePath` / `drawNeckBase`，画在 `drawNeck` 之前、`drawTorso` 之下。**

绘制顺序变为：

```
drawNeckBase   ← 新增（颈肩过渡，最底）
  drawNeck     ← 脖子
    drawTorso  ← 衣领压上来
      drawHairBack → 脸 → 五官
```

形状：下颌内侧 `(±0.36 rx, 0.82 ry)` → 颈侧 → 斜方肌 → 肩峰内侧 `(±0.92 hw, 2.02 ry)`，两段贝塞尔。三条约束缺一不可：

1. **上段必须收得紧**。斜方肌若从脖子中段就开始外斜，视觉上是"耸肩"，脖子短得像嵌进肩膀里。
2. **下段要快速展开到肩峰**，否则洞口照旧。
3. **顶边塞进脸内**（0.82 ry 处脸宽 ±0.45 rx > 顶边 ±0.36 rx），上缘永远被脸压住，不露直边；**外端收在肩峰内侧 0.92 hw**，正压在躯干肩点下方，再往外会在肩头上方露一条肤色。

配色 `shade(skin[0], 0.58) → shade(skin[1], 0.62)`，偏暗 —— 那里本是下颌投影里的暗部，画亮就像没穿衣服。另加下颌投影 + 两抹冷光区分颈侧与斜方肌。

脖子同时加宽到 `±0.44 / ±0.60 rx`，并补圆柱明暗（中亮、两侧入暗）。

**验证（六形象差分法）**

单一形象无法判断某像素是人物还是背景（墙纸本身有明暗和纹样）。利用"**六形象共用同一张背景**"这一点：

- 若采样点仍透背景 → 六帧该点颜色**完全一致**（色距 0）；
- 若已被人覆盖 → 必然随形象肤色变化（skin 六个值各不相同）。

采样 `|x| = 0.78 rx`、`y = 1.05/1.20/1.35/1.50/1.62 ry`，左右各 5 点：**10/10 点色距 4.6 – 25.4，全部 > 3 —- ★ 无空洞**。

破绽回归：0/24 非单调，最小档差 15.3。颈肩层不触及面部（脸最后绘制并完全覆盖落点区），对 SDT 映射无影响。

### 7.9 （2026-10-08）第四版：肩坡上提 + 颈肩轮廓

**症状**：7.8 补完颈肩层之后，视觉上脖子**仍然"透明"**，能看到后方的墙纸线条。

**根因分析 —— 不是 alpha，也不是绘制顺序**

`grep globalAlpha` 只有一处（织纹），且颈肩层是 `fill()` 实心填充。真正的原因有两条，必须同时成立才解释得了"看着是透明的，其实是不透明的"：

| # | 原因 | 证据 |
|---|---|---|
| ① | **肩坡起步太低**：斜方肌从颈根 `(±0.94 rx, 1.68 ry)` 才起坡，下巴 `1.03 ry` 就收完，中间 `0.65 ry`（≈64 px）的落差里，颈侧到肩之间是**真实的背景**——不是没画，是没有形状延伸过去 | 逐行半宽扫描：`y = 1.15 → 1.55 ry` 的半宽长期停在 `0.7 – 1.2 rx`，直到 `1.75 ry` 才跳到 `1.9 rx`，中间是"平台" |
| ② | **暗色叠暗色且没有轮廓线**：颈肩层是压暗肤色，背景是暗棕墙纸，明度差只有十几；皮肤层也无描边，边缘直接融进墙里 | 6 形象品红差分后，颈侧一带的前景/背景边界几乎无法从色差上定位 |

第 ② 条是这条 bug 反复出现的真正原因：**问题不是"没填上"，是"填上了但看不出边界"**。

**修法（四处必须联动）**

| # | 位置 | 改动 |
|---|---|---|
| ① | `torsoPath` 斜方肌段 | 颈根 `1.68 ry → 1.38 ry`；肩坡控制点同步内收（`hw*0.90, 1.74ry` / `hw*0.46, 1.48ry`）；肩峰转角保持在 `2.02 ry` |
| ② | `drawNeckBase` | 轮廓线 `rgba(10,7,5,0.42)` / 1.5px；下颌投影 `0.32 → 0.46`；两侧锁骨上方补斜向冷光 `rgba(245,208,138,0.10)`，把颈侧与斜方肌切开 |
| ③ | `drawNeck` | 加宽 `±0.44 / ±0.60 rx`；渐变提亮 `0.62/0.80 → 0.76/0.96`；颈侧描边 `rgba(10,7,5,0.34)` |
| ④ | 衣领 / 驳头 / 内搭 V（`vGeom` 及其引用） | 20 处硬编码坐标批量上移，与躯干颈根同步 |

④ 不可省：领口 V 的 `topY` 与躯干颈根共用同一组几何。只提躯干不提领口，等于把缺口从"颈肩之间"搬到"下颚与领口之间"。

**验证：逐行封闭空洞扫描（判据比 7.8 更硬）**

对 `y = 0.95 → 1.85 ry`（步长 0.05，共 19 行），在 `x ∈ 头心 ± 2.6 rx` 窗口内找最左/最右前景像素，统计**被它们夹住**的背景像素最长连续段；> 3 px 判为空洞。

前景/背景用**品红帧差分**：把同一形象的皮肤/头发/衣料/胡须换成极端色另渲一帧，两帧完全相同的像素必是背景。

> **坑（已记录）**：只靠"两帧色差"会把**硬编码颜色的部件误判为背景**。第一版扫描报了 3 个形象有洞（最长 14 px，位置全在 `x = 440` 正中竖线），取色为 `rgb(126,52,41)` —— 是**领带** `#6E1F22` 被灯光提亮后的颜色；同行背景参考 `rgb(31,23,15)`。领带在品红帧里不换色，因而被算成"夹在中间的背景"。
> **修正**：判据追加"颜色必须同时接近同行背景参考色（色距 < 45）"。

最终：**六形象 0 / 19 行有洞 —— 颈肩区完全闭合。**

**回归**：破绽 6 形象 × 4 落点 × `tell = −2…+2` → 非单调 **0/24**，最小档差 15.5，底色极差 24.3（面部代码未动）；`node --check` 9/9、`selftest` 43/43；真实游戏页 canvas 912×570（1.600）、视口 1314×760 溢出 0 px、0 控制台报错。

## 8. 技术架构

### 8.1 文件结构

```
liars-bar-sdt/
├─ index.html              单页入口（含 <canvas> 与各面板容器）

│   ├─ params.js           参数与常量集中定义
│   ├─ engine.js           试次生成 + 单试次状态机
│   ├─ render.js           Canvas 场景绘制（桌面/卡牌/对手含颈肩过渡/破绽噪点）
│   ├─ audio.js            Web Audio 合成音效（可关）
│   ├─ charts.js           分布图 / ROC / 心理测量函数（Canvas 自绘）

│   └─ main.js             入口与流程编排
├─ README.md
└─ docs/DESIGN.md          本文件
```

### 8.2 关键工程决策

- **零依赖**：图表不用 Chart.js，用 Canvas 自绘（本项目只画正态曲线、ROC、柱状图，自绘代码量可控且能离线跑）。
- **无构建**：不引入 npm / 打包器。助教 `git clone` 后双击 `index.html` 即可。
- **模块化**：每个 `js` 文件一个职责，`stats.js` 纯函数、可单独单元验证（附一个 `docs/stats-selfcheck.html` 手算用例页，验证 `d′ = 1.00` 等已知结果）。
- **注释规范**：每个函数带 JSDoc；每个公式旁写明出处（文件名 + 页码/DOI）。
- **不使用 Flask**：作业明确"纯前端即可"，不引入不必要的后端依赖。

## 10. 需要你拍板的四个问题

1. **证据通道**：用现在的"噪点破绽显影"（数学干净、可控），还是换成更贴原型的"算牌推理"（对手报的点数 vs 桌面剩余牌数，更有牌局味，但 d′ 难精确控制）？
   —— 我的建议：**主通道用破绽显影，把"算牌"做成情境装饰**，两者兼得。

2. **罚酒血条**：要不要给玩家 3 瓶酒的"命"？
   —— 我的建议：**默认关闭**。因为一旦血量会影响决策，玩家的门槛 c 会在一局内漂移，破坏 `p(H)`、`p(FA)` 的平稳性假设（估出的 d′ 会失真）。血条可以只做视觉反馈、不影响判定。这一点建议写进 README 当方法学说明。

3. **置信度评分**：要不要加"高/低置信"二级评分？
   —— 加了就能画**经验 ROC**（2 个点），加分更有说服力，但每试次多一次点击，会拖慢节奏。我的建议：**默认关，结算页可开启**。

4. **多局记录**：只存本地（localStorage）够吗？
   —— 够了，且符合"纯前端"要求。若你想要跨设备排行榜才需要后端，我不建议为此引入 Flask。
