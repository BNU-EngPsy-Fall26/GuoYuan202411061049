# 骗子酒馆 · 识谎局

一个**信号检测论（Signal Detection Theory）交互式实验网站**，把"识破对手吹牛"做成了一个标准的 Yes/No 检测任务。

原型参考 `Liar's Bar`（中文译名"骗子酒馆 / 骗子酒吧"，Curve Animation 开发并发行，2024-10-02 Steam 抢先体验上线，获 2024 年 Steam 大奖"最具创意游戏玩法"）。

---

## 一、怎么跑

**方式一（推荐）**：直接双击 `index.html`。

不需要 npm、不需要装依赖、不需要起服务器、不需要联网。
`file://` 协议下也能完整运行 —— 代码刻意使用传统 `<script>` 标签而非 ES module，
就是为了避开 `file://` 下的 CORS 限制。

**方式二**：起个本地服务器（想用 localStorage 之外的调试功能时）。

```bash
python -m http.server 8000
# 然后打开 http://localhost:8000
```

**验证公式算得对不对**：

```bash
node docs/selftest.js
```

43 项自检全部通过，包括教科书算例往返、极值修正、以及一个"理想观察者"的端到端模拟。
详见下文「七、自检」。

## 二、怎么玩

每一轮，对面的酒客把牌推到你面前，报出一个点数。你要判断的只有一件事：
**他在说谎，还是在说实话。**

- **他在说谎 = 信号（S）**，**他说实话 = 噪音（N）**
- 按「你骗人」= 报有信号，按「相信他」= 报无信号
- 快捷键：`J` 相信，`K` 揭穿；开启置信度后 `1` / `2` 评分

单试次流程：**发牌喊牌（0.8s）→ 观察窗（默认限时 3 秒，环形倒计时）→ 你的判断 → 揭示计分（1.2s）→ 间隔（0.6s）**。

观察窗超时会按「相信」计入，并在记录里标记为超时。

## 三、信号检测论映射

| | 你喊「你骗人」（Yes） | 你说「相信他」（No） |
|---|---|---|
| **他在说谎（S）** | **H 命中** — 抓到了，你 +1 | **M 漏报** — 被他骗了，你 −1 |
| **他说实话（N）** | **FA 虚报** — 冤枉好人，你 −1 | **CR 正确拒绝** — 稳稳跟牌，你 +1 |

结算自动计算：

```
命中率   p(H)  = H / (H + M)
虚报率   p(FA) = FA / (FA + CR)

辨别力   d′    = z(p(H)) − z(p(FA))          z = Φ⁻¹，标准正态逆累积分布
判断门槛 c     = −0.5 · [ z(p(H)) + z(p(FA)) ]   c > 0 保守，c < 0 激进
似然比   β     = exp(c · d′)                 β > 1 保守，β < 1 激进
准确率   ACC   = (H + CR) / 总试次
```

**可调节参数**：

| 参数 | 范围 | 含义 |
|---|---|---|
| 辨别力 d′ | 0.2 – 3.0 | 破绽有多明显（客观难度） |
| 先验概率 P(S) | 0.10 – 0.90 | 他有多大比例在骗人 |
| 每局试次数 | 20 / 40 / 60 | 硬性满足"每局 ≥ 20 试次" |
| 观察窗限时 | 不限时 / 3 秒 / 5 秒 | 刺激限时 |
| 置信度评分 | 开关 | 开启后每次判断多答一次「高/低置信」，结算才能画**经验 ROC** |

## 四、方法学说明（给助教看的）

这一节是本项目最该被检查的部分，也是我认为它区别于"一个套了皮的小游戏"的地方。

### 4.1 证据通道是显式生成的，d′ 是被"设计"出来的

每个试次分两步生成（`js/engine.js`）：

1. **客观状态**：说谎 / 说实话，由区组随机配额指定（见 4.3）
2. **内部证据 x**：`x | N ~ Normal(0, 1)`，`x | S ~ Normal(d′, 1)`

于是两条分布在证据轴上的**标准化间距就是 d′** —— 它是设计参数，不是事后从玩家数据里拟合出来的。
这是本程序能做"真值对照"的根本原因。

之后才把 x 变成玩家看得见的东西：

```
呈现强度   tell = clamp(x + ε, −3, +3)，  ε ~ N(0, σ_disp²)，σ_disp = 0.5
归一化强度 k    = (tell + 3) / 6                       ∈ [0, 1]
破绽不透明度    = 0.05 + 0.92 · k
破绽柔光半径    = 15 + 32 · k                    （px）
破绽核心亮点    = 0.10 + 0.90 · k，半径 2.5 + 7.5 · k
头肩抖动幅度    = 0.3 + 8.0 · k                  （px）
```

**为什么要先归一化再映射，而不是直接在 tell 上乘增益**：直接在 tell 上乘增益时，
负的 tell 会把不透明度压到 0 以下被截断 —— 一半的噪音试次会挤在同一个下限上，
那一段的信息就被抹掉了，设定的 d′ 在画面上失真。归一化保证整条 ±3σ 区间都
**严格单调**，不截断、不并合。

**为什么用四个通道而不是一个**：d′ 对严格单调重映射是不变的（H 与 FA 在对应判据下的
取值不变），所以多开几个视觉通道**不会**改变理论上的 d′_eff，只是把同一份信息摊到
更多可感知的维度上（亮度、面积、锐边、运动），让人更容易读。是"同一份信息、更好的
可读性"，不是"偷偷加料"。

（2026-10-06 修订：初版只有"柔光不透明度"一个通道，`tell = 0` 与 `tell = 1` 之间只差
0.26 的不透明度，且破绽被画在颗粒噪点层**下面**，被糊掉一层对比度，实际几乎读不出来。
现版本改为四通道联动，并把绘制顺序调到噪点之上。
2026-10-08 美术重做后复测：破绽区域平均亮度在**六人物 × 四落点 × `tell = −2 … +2`** 共 24 组里
**全部严格单调**，底色 67.8–88.7、跨度 74.4–84.7、最小档差 16.2–18.8，非单调 0/24。）

**为什么要有 σ_disp 这一项**：如果 x → 画面是完全确定的一一映射，玩家理论上能达到的辨别力没有
上限，我们设定的 d′ 就只是一句空话。加入独立的显示噪声后，两条分布在证据轴上的间距依然是 d′，
但方差变成 `(1 + σ_disp²)`，于是**客观可辨性的天花板**是：

```
d′_eff = d′ / √(1 + σ_disp²) ≈ 0.894 · d′
```

结算界面同时显示「生成 d′」「理论上限 d′_eff」「你估出的 d′」三个数，让真值对比有意义。
自检脚本里"理想观察者"实测 d′ = 1.333，理论上限 1.342 —— 吻合。

**诚实地说**：这本质上就是教科书里最经典的"噪声背景中检测目标"任务，外面套了一层酒馆的皮。
皮是皮，骨是骨，两者不混 —— 这也是为什么 README 能把整条生成链写清楚。

### 4.2 极值修正用 log-linear 规则，并在界面上明说

某格为 0（例如一局里一次都没虚报）时，p 取到 0 或 1，z 值发散。
程序自动改用 **log-linear 规则**（2×2 表每格加 0.5），并在结算页打出「已修正」标记与依据 ——
不悄悄改数据。

依据是 Hautus (1995) 用 5 万次蒙特卡洛比较了 log-linear 与 `1/(2N)` 两种规则：
log-linear 偏差更小，且总是低估总体 d′。

### 4.3 用区组随机配额，而不是每个试次独立掷骰子

独立抽样时，`P(S)=0.1` + 20 试次的设置有 `0.9^20 ≈ 12%` 的概率一个信号试次都抽不到，
命中率直接算不出来。改用**配额 + Fisher–Yates 洗牌**后，先验概率恰好等于设定值，
且两类试次必然非空。自检脚本对四种参数组合都做了验证。

### 4.4 为什么默认不给玩家"血条"

原型游戏里被识破要喝罚酒、甚至俄罗斯轮盘。但**一旦惩罚会影响后续决策，玩家的门槛 c 会在一局之内漂移**，
`p(H)` 与 `p(FA)` 的平稳性假设就破了，估出来的单一 d′ 是失真的。

所以本程序只保留"罚酒"的叙事与动画反馈，计分采用**对称收益（判对 +1 / 判错 −1）且不影响后续试次**。
这样既保住了代入感，又让 d′ 与 c 的估计在方法学上站得住。

顺带一个好处：对称收益下贝叶斯最优门槛有干净的理论解
`β_opt = P(N)/P(S)`，`c_opt = ln[P(N)/P(S)] / d′` —— 结算页会把它和你的实际门槛摆在一起对比。

### 4.5 试次期间整屏不打滚（这条是反应时能不能用的前提）

游戏屏在运行时会锁掉页面滚动（`body.playing`），画面高度按视口切好，Canvas 再等比缩放去填空，
**酒客 / 喊牌 / 按键提示 / 判断按钮 / 置信度按钮永远同屏**。

这不是审美问题：反应时从观察窗开始计时，只要玩家需要滚动才能按到按钮，那段滚动时间就被
算进了 RT，反应时数据立刻失真。同理，喊牌内容与 J / K 提示都画进 Canvas 内部并贴着对手，
避免视线在页面上来回找 —— 视线移动的时间同样会进 RT。

> 2026-10-06 修订：初版是流式布局，Canvas 宽度铺满、高度自适应，在常见笔记本
> （视口高 700–900 px）上必然把按钮挤到折叠线以下。已改为视口自适应的弹性布局，
> 并在 1340×668 / 1894×980 / 2534×1340 三种视口下实测：文档溢出均为 0 px，最低元素底边
> 均在视口之内。

### 4.6 其它

- **状态推进不用 rAF**：`requestAnimationFrame` 在后台标签页会被浏览器暂停，
  玩家切一下窗口流程就断在半路。所以推进用定时器，rAF 只负责画。
- **记录内部证据 x**：玩家看不到，但每试次的 x 会被存下来，局末按 x 分箱画出
  **经验心理测量函数** `P(揭穿 | x)`，反推你的主观门槛在哪。
- **开局页有"破绽强度对照表"**：**本局抽到的那张脸**在 `tell = −2.5 … +2.5` 六档下的样子并排摆开。
  开打前先看一眼，玩家心里就有一把尺子，能显著压缩练习效应；
  这张尺子只展示映射本身，不泄露任何一局的真值。
  （2026-10-08：尺子改为用本局真实形象渲染，见 4.7）
- **随机数可播种**（`js/rng.js`，mulberry32）：给定同一个种子可完整重放整局，便于排查与写报告。
  注意**对手形象不走这条 RNG 流**（`Math.random` 独立抽取），否则固定种子会连带固定形象，
  "可复现"就变成了"可预知"。

### 4.7 画面美术与形象随机（2026-10-08 重做）

初版人物是形状堆砌（椭圆脸 + 矩形身 + 圆点眼），背景纯色渐变，桌面没有道具。这一轮按四条要求重做：

**① 桌面酒具** —— 一瓶**开着的酒**（酒液灌到瓶颈下沿、软木塞拔出后躺在桌上、瓶身贴酒标）+ 一支**装着红酒的高脚杯**（弯月液面 + 玻璃高光）；台呢加斜纹织物质感。

**② 墙面与氛围** —— 程序化生成的**菱花卷草暗纹墙纸**平铺 + 檐口线 + 护墙板竖棱 + 顶灯光锥 + 两幅装饰画（港湾夜景 / 散落纸牌）+ 两盏会呼吸的壁灯 + 暗角。

**③ 六种对手：男女 × 老中青** —— 青年男 / 中年男 / 老年男 / 青年女 / 中年女 / 老年女，
动漫风格程序化绘制（贝塞尔尖下巴脸型、五缕交错刘海 + 内收鬓角、虹膜径向渐变、帽子/眼镜/耳环/项链/领结等配饰）。
一局抽一次、整局不变，HUD 参数行会显示本局对手是谁。

**④ 公平性硬约束（这条是方法学问题，不是审美问题）** —— 破绽是脸上的亮斑，**任何形象自带的亮色落在破绽点上，就等于给那一局偷偷改了难度**。所以：

- 破绽四个落点（眉梢 / 眼角 / 嘴角 / 颧骨）避开眼白与镜片中心
- 巩膜统一压暗为 `#CFC4AE`，不用纯白
- 老年形象的发色逐级压暗，垂发与鬓角内缘收进 `0.80rx` 之外

像素探针实测（6 人物 × 4 落点 × `tell = −2 … +2`）：

```
底色（tell = −2）  min 67.8  max 88.7  极差 20.9
跨度              min 74.4  max 84.7
最小档差          min 16.2  max 18.8
非单调组数        0 / 24
```

修订前老年女的底色是 110 / 97 / 95、其余人物 50–70，极差 **60** —— 确实存在难度泄漏，
已压到 **20.9**。六张脸上破绽都严格单调可读，形象之间不偷换难度。

### 4.8 第二版美术修订（2026-10-08 晚）

上一版把脸做细了，但**身体和卡牌还是"形状的堆砌"**，卡面下面那行小字也挤得看不清。这一轮针对这三点重做。

**① 躯干：从"一个圆角色块"改成一件有结构的衣服**

旧版是两条二次曲线围成的一大块纯色 —— 没有肩、没有臂、没有领。现在按十层画：

```
底形 → 体积与织纹 → 轮廓线 → 肩部轮廓光 → 臂缝（袖窿）
     → 衣领座 → 内搭（衬衫/马甲）→ 驳头 → 细节 → 褶皱
```

几个关键点：

- **肩不再是"一道坡"**。拆成三段：斜方肌（平缓）→ 肩峰转角（陡）→ 三角肌外圆（往外撑开）。少了转角那一段，整个人就是一座山。
- **臂缝（袖窿）**从肩点往内下方收进腋下，再顺胳膊垂下，在身体两侧各切出一条约 60 px 宽的袖子。而且用"宽阴影带 + 缝线 + 受光边"三笔写 —— 单画一条细线在深色大衣上等于没画。
- **驳头带缺口**（平驳头）。这个缺口是西装最好认的特征，没有它整件就像浴袍。驳头、内搭、前襟**共用同一组 V 边控制点**，所以两片衣服严丝合缝，不会出现"驳头压不住衬衫、露出一条缝"。
- **衣料加了人字呢织纹**（程序化生成的 16×16 贴片平铺）。只有一块平色的话，轮廓画得再准也像纸片。
- **配色整体提亮**。上一版 `#2C2219` 这种近黑的大衣在暗场里根本看不出层次，六件衣服的基色都上调了一档（如青年男 `#2C2219 → #3E3124`）。
- 按形象换衣着：`wear` 字段分 `vest / suit / cardigan / blouse / dress / shawl`，分别对应马甲+领带、正装+口袋巾、开衫+一排扣、罩衫+胸针、连衣裙、披肩。

**② 画序调整：人物挪到桌子后面**

`drawTable` 从人物**之前**挪到**之后**。台呢于是会盖住上身的下沿，人物变成"坐在桌子后面"，而不是一尊悬在桌沿上的半身像。（桌上酒瓶在 x=175、酒杯在 x=705，离人物 ±200 很远，不会被压住。）

**③ 卡牌：从"圆角矩形 + 两条交叉线"改成真扑克**

- **牌面**：纸面渐变 + 双线内框 + 左上/右下两组角标（右下那一组倒过来）+ 中央大花色。四个花色（♠♥♦♣）都是矢量画的。
- **牌背**：红底渐变 + 米色双线框 + 斜向菱格 + 中央椭圆徽章（内嵌黑桃）+ 四角小菱形。
- **纸的厚度**：牌身下面压一层 2.2 px 的暗色 —— 一张牌是有厚度的纸，不是一个贴纸。
- ★ **花色由牌面唯一决定**（`RANK_SUIT` 写死的映射），所以它不多带任何信息。玩家要比的始终只是"牌面 vs 他喊的牌"。写死而不是每局随机抽，是为了让同一局重放时画面完全一致。
- 揭示时的红叉/绿勾改成"先用暗色描一层外缘、再上色、再补一道高光"，尺寸收到贴着牌组，并整体旋转 −0.05 rad —— 旧版那两道横跨半个屏幕的直线太粗糙了。

**④ 删掉卡面下面那行小字**

旧版在牌心下方 28 px 处写"不是他要的牌 / 正是他报的牌"。删掉，理由是**它完全冗余**：同一条信息已经在三处表达过了 ——
画面顶部的大字判定（抓到了 / 被他骗了 / 你冤枉了他 / 他没骗你）、画布下方的结果条（H/M/FA/CR + 反应时）、以及压在图上的那一笔红叉或绿勾。

而且它挤在一张 70 px 宽的牌里，既看不清，又把牌面挡掉一半。**信息没有丢，只是不再重复第五遍。**

顺带把顶部那行大字加了底衬 —— 它刚好压在对手的帽子/头发上，不给底衬时字和头发糊在一起，而这行字是玩家唯一能立刻读到"这局算对还是算错"的地方。

**验证**（无头 Chrome + 像素探针）：

- 六形象整场景对照图 + 3 倍躯干特写，逐张人工核对（截图见交付说明）。
- 卡牌区逐点检查：旧小字位置暗像素 **0**（旧版会贡献 40+）、中央大花色 1017、右下角标 141、红叉 467、绿勾 509、牌背徽章 205 —— 全部到位。
- 破绽单调性回归：6 人物 × 4 落点 × `tell = −2…+2`，**非单调 0 / 24**，最小档差 15.7。
- 完整一局：20 试次 + 20 次置信度，视口 1314×568 文档溢出 0 px，最低元素底边 558/568，控制台 0 报错。

### 4.9 第三版美术修订：颈肩过渡层（2026-10-08）

**问题**：头是悬空的 —— 下巴和身子之间什么都没有，直接透出墙纸。

根因是一个纯几何的缺口：脸的下巴在 `1.03 ry` 就收完了，脖子只有 `±0.6 rx` 宽，而躯干的肩线要从颈根 `(±0.94 rx, 1.68 ry)` 才起步。于是在 `|x| ∈ [0.52, 0.94] rx`、`y ∈ [1.03, 1.65] ry` 这**两片三角形区域**里，没有任何图元覆盖 —— 左边的墙纸就从那儿透出来。

**修法：补一层 `drawNeckBase`（颈肩过渡），画在脖子之前、躯干之下。**

它按解剖走：下颌内侧（`±0.36 rx, 0.82 ry`）→ 颈侧 → 斜方肌 → 肩峰内侧（`±0.92 hw, 2.02 ry`）。分两段贝塞尔，**上段收得紧、下段才展开**：

- 上段不收紧，斜方肌从脖子中段就开始往外斜，看着就是"耸肩"，脖子会短得像嵌进肩膀里；
- 下段不展开，就还是留着那块洞。

两个细节：

- **顶边故意塞进脸里面**（`0.82 ry` 处脸宽 `±0.45 rx`，顶边只有 `±0.36 rx`），所以它的上缘永远被脸压住，不会露出一条直边。
- **外端收在肩峰内侧**（`0.92 hw`），正好压在躯干肩点下方 —— 再往外延就会在肩头上方露出一条肤色。

配色压得比较暗（`shade(skin[0], 0.58) → shade(skin[1], 0.62)`）：那里本来就是下颌投影里的暗部，画亮了反而像没穿衣服。另加一道下颌投影和两抹冷光，把颈侧与斜方肌分开。

顺带把脖子从 `±0.40/0.52 rx` 加宽到 `±0.44/0.60 rx`，并补了圆柱明暗（中间亮、两侧收进暗部），一根柱子才立得起来。

**怎么验证"没有洞"**（这条比视觉检查更硬）：

取 `|x| = 0.78 rx`、`y = 1.05 / 1.20 / 1.35 / 1.50 / 1.62 ry` 共 10 个采样点，在**六个形象**下各采一次：

- 六个形象共用同一张背景 → 若某点还透背景，六个值必然**完全相同**；
- 若已被人物覆盖，它必然随该形象的肤色变化。

实测 10/10 点的"形象间最大色距"为 4.6 – 25.4（全部 > 3），判定 **★ 无空洞**。修订前的同一测法会在这些点上得到 0。

破绽回归同时复测：6 形象 × 4 落点 × `tell = −2…+2`，**非单调 0 / 24**，最小档差 15.3，底色（tell=−2）极差 25.1 —— 颈肩层不在脸上（脸最后画、完整覆盖），所以对信号检测映射零影响。

### 4.10 第四版美术修订：肩坡上提 + 颈肩轮廓（2026-10-08）

**问题**：4.9 补完颈肩层之后，视觉上脖子**依然"透明"**，仍能看到后面的墙纸线条。

**根因不是 alpha，也不是绘制顺序** —— 而是两条叠加：

1. **肩坡起步太低**。`torsoPath` 的斜方肌从颈根 `(±0.94 rx, 1.68 ry)` 才起坡，而下巴 `1.03 ry` 就收完了。中间那 `0.65 ry`（约 64 px）的落差里，脖子两侧到肩之间是一整片**真实的背景**，不是没画，是根本没有形状延伸到那里。
2. **暗色叠暗色 + 没有轮廓线**。颈肩层与脖子本身是压暗的肤色，背景是暗棕墙纸，两者的明度差只有十几；加上皮肤那层没有描边，边缘就"融"进墙里 —— 看上去像一块半透明的皮肤，其实是不透明的，只是看不出边界。

第 2 条是这条 bug 反复出现的真正原因：**问题从来不是"没填上"，是"填上了但看不见边界"。**

**修法**（四处联动）：

| # | 位置 | 改动 |
|---|---|---|
| ① | `torsoPath` 斜方肌段 | 颈根 `1.68 ry → 1.38 ry`，肩峰转角控制点同步内收，肩坡整体上提约 29 px |
| ② | `drawNeckBase` | 加**轮廓线** `rgba(10,7,5,0.42)`；下颌投影 `0.32 → 0.46`；两侧锁窝上方加抹冷光把颈侧和斜方肌分开 |
| ③ | `drawNeck` | 加宽到 `±0.44 / 0.60 rx`；渐变提亮（`0.62/0.80 → 0.76/0.96`）；颈侧补轮廓线 |
| ④ | 衣领 / 驳头 / 内搭 V | 共用控制点整体上移（20 处硬编码坐标批量替换），否则领口会留在原地、和下巴之间又裂开一道 |

④ 是必须的：领口 V 的 `topY` 与躯干颈根是**同一组几何**，只动躯干不动领口，等于把洞从"颈肩之间"搬到"下颚与领口之间"。

**怎么验证**（这次判据比 4.9 更硬）：

逐行扫 `y = 0.95 → 1.85 ry`（每 0.05，共 19 行），在该行 `x ∈ 头心 ± 2.6 rx` 的窗口里找出最左/最右的前景像素，再数**被它们夹住**的背景像素最长连续段（> 3 px 即判为空洞）。前景/背景用**品红帧差分**判定：把同一形象的所有皮肤/头发/衣料换成极端色再渲一帧，两帧完全相同的像素必是背景。

这里有个坑值得记：**光靠"两帧色差"会把硬编码颜色的部件误判成背景**。第一版扫描报了 3 个形象有洞，最长 14 px、位置全在 `x = 440`（画面正中竖线）—— 取色一看是 `rgb(126,52,41)`，正是**领带**（`#6E1F22` 被灯光提亮），同行背景参考是 `rgb(31,23,15)`。领带在品红帧里没有换色，于是被判成"夹在中间的背景"。

所以判据再加一条：像素颜色必须同时**接近同行背景参考色**（色距 < 45）才算洞。

最终结果：**六形象 0 / 19 行有洞**，颈肩区完全闭合。

**回归**：6 形象 × 4 落点 × `tell = −2…+2` → **非单调 0 / 24**，最小档差 15.5，底色极差 24.3（脸没动，映射干净）；`node --check` 9/9、`selftest` 43/43；真实游戏页 canvas 912×570（比例 1.600）、视口 1314×760 文档溢出 **0 px**、HUD 参数行正常、控制台 **0 报错**。
